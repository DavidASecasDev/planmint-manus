# Verificación visual segura de SES.HOSPEDAJES

La preview normal de PlanMint **sí está conectada al proyecto Supabase de producción**. Técnicamente, el cliente restaura una sesión Supabase persistente y los hooks SES invocan endpoints Express; estos endpoints construyen sus clientes con `SUPABASE_URL`, que en este proyecto corresponde al host de producción. Por ello, abrir `/ses-hospedajes` con una sesión válida puede mostrar datos reales en tiempo de ejecución.

Esta conexión no implica que Manus haya copiado esos registros al repositorio. En esta revisión no se creó ninguna fixture desde respuestas de producción y no se ejecutaron operaciones SES. Al auditar los registros técnicos se detectó que el colector de desarrollo había persistido localmente tráfico de una sesión previa de la preview normal, incluidos cuerpos y cabeceras. Esos logs locales se eliminan antes de la entrega y el colector queda endurecido para guardar únicamente método, ruta sin query, estado, duración y un indicador de fallo; también redacta el contenido de consola y sesión. `.manus-logs` no forma parte del repositorio ni del checkpoint.

Para evitar ambigüedad, toda verificación visual automatizada de SES debe usar exclusivamente `/__fixtures/ses-hospedajes`, servida dentro de `setupVite`, que solo se activa cuando `NODE_ENV=development`. Su entrada `client/ses-hospedajes-fixture.html` no importa autenticación, Supabase, `apiInvoke` ni `useSesHospedajes`; renderiza únicamente constantes `SYNTHETIC-*`. No es una ruta de la aplicación operativa ni forma parte del grafo de entrada de `client/index.html` usado por el build de producción.
